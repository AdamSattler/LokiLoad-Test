# VB.NET Code Refactoring Challenge – `SendSMSMessage`

Welcome to the Code Refactoring Challenge! This Visual Basic project is part of our developer interview process. The goal is to evaluate your ability to improve and modernize existing code through thoughtful refactoring.

---

## 🎯 Objective

Your task is to **refactor the `SendSMSMessage` function** in the `MessageManager.vb` class.

We’re looking for clean, idiomatic, and maintainable code that preserves the original behavior of the function.

---

## ✅ What We're Looking For

We'll evaluate your submission based on:

- **Code clarity and readability**
- **Modular design and separation of concerns**
- **Use of appropriate VB.NET / .NET Framework features**
- **Maintainability and simplicity**
- **Correctness** – the function must behave the same after refactoring
- **Presence of a working unit test**

---

## 🧪 Testing Requirement

You must write at least **one unit test** that verifies the behavior of `SendSMSMessage` before and after your changes.

- You can use any .NET Framework-compatible testing framework (e.g., MSTest, NUnit, xUnit)
- Place your test class in a separate folder (e.g., `/Tests`)
- Include clear input/output assertions to show the function still behaves as expected

> 💡 Feel free to mock any external dependencies or outputs.

---

## 🚀 How to Run

This is a **.NET Framework** project. To build and run:

1. Open `LokiLoad.Test.sln` in **Visual Studio 2019 or later**
2. Build the solution
3. Run your test using the Test Explorer in Visual Studio or IDE of your choice

> 🧰 If needed, you can add a new test project to the solution.

---

## 📬 Submission Instructions

You can submit your work in one of the following ways:

### Option 1: GitHub Fork
1. Fork this repository
2. Commit your changes and unit test(s)
3. Share the link to your repository

### Option 2: ZIP Archive
1. Zip the entire project folder (including your refactored code and unit tests)
2. Include a brief `RefactoringNotes.txt` or update this README with:
    - A summary of your improvements
    - Any assumptions or design decisions
3. Send the archive as instructed

---

## 🧠 Tips

- Small, meaningful changes go a long way
- Add helper methods or new classes if needed
- Comment where clarification is helpful, but clean code should speak for itself
- Don't over-engineer—keep things maintainable and understandable
